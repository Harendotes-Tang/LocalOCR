# 自动颜文字区域研究

本工具维护独立的离线 CPU 研究链路：通用文字首遍识别、图像候选定位、专项识别与保守融合。研究结果不更改 `0.1.0-rc.2`、活动模型、HTTP API、CLI 或 `localocr.bundle.v1`。APP 区域选择、取消及预览生命周期由应用工程独立验收。

## 数据与推理边界

本轮原创整图数据包含 200 张开发图和 400 张保留图，分别记录 120 与 280 个颜文字区域。真实墨迹掩码、原图半开坐标 `[left, top, right, bottom)` 和原始 Unicode 跨度由生成器保存；详细契约见 [SCENES.md](SCENES.md)。字体和词汇原子可以共享，布局家族、非空标签和跨分区像素互斥。有限原创配方的结果不能直接代表任意真实截图。

`inference-inputs.json` 仅包含图片标识、相对路径、容器及像素 SHA-256、宽度和高度。推理子进程不接收标签、真值区域、字符跨度或掩码。评测主进程在推理完成后读取真值并计算指标；真值不参与推理时的候选生成、裁片、路由或融合。开发指标用于模型与路由选择；保留集仅在选择冻结后首测。

私人图片、标签、逐项预测、字体和模型权重仅保存于忽略的 `artifacts/`。原创数据采用 CC0-1.0，生成器遵循 GPL-3.0-or-later，字体遵循各自 OFL 许可并不随数据分发。

## 定位与融合

候选分别来自首遍文字/几何及原图像素。图像来源可以补充首遍检测器遗漏；配对括号形状与像素空白带只提供结构线索，不证明具体 Unicode 码点。

每个送入专项识别的候选使用原裁片及加边裁片，两视图由同一实际模型识别。融合要求原始识别字符串一致、独立裁片像素摘要不同、结构与邻域证据满足约束；不比较不同模型的原始分数，不补括号、修剪空格或归一化输出。不确定、裁片不完整、视图不一致或正文锚点有歧义时保留首遍结果。

首遍 OCR 把正文与颜文字合并到一个宽框时，只有真实像素分界、左右剩余裁片复读及唯一原文前后缀绑定同时成立，才允许局部替换。正文按原始字符串保留；不按字符数估算单字坐标。研究记录保留首遍框和分数、专项区域、上下文依据、模型输出与融合决定，额外复读时间计入 CPU 资源。

混合框的候选与上下文复读绑定首遍区域索引、原图框及原始文本的规范摘要；父文本或位置变化即拒绝融合。多个首遍区域合并时，原始串接结果必须构成单个完整表达式；并排两个完整颜文字保持各自结果，不能将其中一个专项输出替换两项。正文字符删除按实际字符串变更计数，不通过扩大的候选框豁免正文保护。

## 实际入口

使用公共 CPU 评测环境和本地固定模型，不执行下载或远程图片获取。

```powershell
$python = 'artifacts/service-env/Scripts/python.exe'
$scenes = 'artifacts/region-kaomoji-20261011/data-v2'
$baseline = 'artifacts/model-store/versions/baseline-1'

& $python -m tools.RegionKaomoji.scenes validate --dataset $scenes
& $python -m tools.RegionKaomoji.evaluate evaluate `
  --dataset $scenes --split dev --baseline-models $baseline `
  --candidate <Tiny微调候选/candidate.json> `
  --candidate <RepSVTR微调候选/candidate.json> `
  --inputs "$scenes/inference-inputs.json" `
  --output artifacts/region-kaomoji-20261011/evaluation-dev-final
```

输出目录必须是本轮 `evaluation*` 命名空间中的新目录；路径越界、重解析点及已有输出拒绝。基线实际执行检测、方向、识别及既有符号复读；候选输出与实际融合分别保存。ONNX 使用 `CPUExecutionProvider`、两个 intra-op 线程和一个 inter-op 线程。

每图限制为 20 MiB 源文件、50M 像素、最多 48 个专项候选、累计 1M 裁片像素及 8 MiB 输出；单图超时 90 秒，整批超时 5,400 秒。多模型视图与正文复读均计入裁片预算，超预算候选保留首遍结果。

两家族最终微调模型及开发路由选择完成后，`freeze-selection` 绑定模型、词表、预处理、实现源码、路由/融合配置、图片索引、开发报告与结束后的 GPU 账本。冻结不等于质量门禁通过。`evaluate --split heldout --selection <冻结凭据>` 在读取保留图片或真值前独占创建首用凭据；失败或重复执行不能重新声明为独立首测。两项研究共用累计 7,200 秒 GPU 上限，整图评测使用 CPU。

## 指标口径

报告分别统计候选发现、完整墨迹覆盖、不吞正文的完整覆盖、预筛资格及实际送模型数量。候选与正文或图形相交和最终误改分别记录，不能把发现召回率当作实际路由成功率。

最终颜文字整串匹配与 CER 使用自动定位、实际模型输出及融合后的结果；实际安全完整的自动裁片成绩另列；既有人工行裁片研究与整图结果分别报告。正文报告基线正确转错、错误改写及混合框变更；图形与空白报告新增非空输出。正确定位而专项识别失败同样计为链路失败。正文混合框保留证据不能证明单字坐标或 APP 接入质量。

公开 README 与图表仅消费匿名计数、资源及哈希；原图、标签、逐项预测和内部路径不进入文档资产。任何候选接入仍要求颜文字改善、普通文字无新增误改、负样本保护、真实区域与像素证据、CPU 资源及应用生命周期验收。

## 本轮冻结结果

开发 200 图完成后冻结模型与路由，再首次评测 400 图。新保留发现 279/280 个颜文字区域，但冻结资格规则实际路由为 0，两专项没有执行任何保留视图识别，最终保持基线：颜文字整串 8/280、CER 69.61%。正文新增错误 0/400、负样本新增非空 0/80；该结果不证明增强有效，不启用研究链路，也不根据保留结果调整规则。

全部 763 个候选的实际拒绝原因是结构未确认 673、普通正文锚点 40、正文相交 33、裁片不完整或边缘截断 17；这是候选分母，不能按颜文字区域数解释。完整计数、冻结哈希和 CPU 资源见[工程 README](../../README.md)及[匿名汇总](../../docs/evaluation/region-20261012/summary.json)。两模型 session 虽实际加载，保留视图数为零，因此资源不能代表专项识别负载成本。
