# 起点配置逐阶段归因（2026-10-29）

状态：只读归因，不改规则、不训练、不推理、不读保留集，GPU 用量为 0。对象是首轮位置绑定轮（2026-10-27）已记录的八份开发报告：起点 `start` 与三个被拒候选档 `initial`、`local`、`union`，各在锚点集（browser-cards-v2 dev，244 面）和新集（browser-cards-v6 dev，268 面）上各一份。起点即候选恢复轮（2026-10-18）冻结后沿用至今的配置；本页数字与该轮 verification.md 和报告 `summary` 逐项一致。结果都是浏览器真实字体渲染，不是真实截图。

## 阶段划分

沿用 2026-10-19 轮的六类定义，每个颜文字目标归入第一个不满足的阶段：

| 阶段 | 含义 |
| --- | --- |
| nohit | 没有任何自动候选触及目标墨迹 |
| partial-only | 有候选但没有一个完整覆盖目标墨迹 |
| complete-but-body/graphicunsafe | 有完整候选，但每个完整候选都含正文或图形像素 |
| safe-unrouted | 有安全完整候选，但没有一个进入专项识别 |
| safe-routed-raw-wrong | 安全完整候选进入专项，原始视图读数全部不等于真值 |
| safe-routed-raw-correct | 至少一个安全完整候选的原始视图读数等于真值 |

“原始视图正确”是对已记录裁片的诊断上界，不是自动选择规则；最终整串仍由融合决定。

## 三个候选档在新集上的丢失

三个候选档在新集上丢失的都是同样三个起点已正确目标：dev-0011 的 region-42 与 region-43、dev-0018 的 region-30。归因结果在三档上完全一致：候选、覆盖、安全、路由和专项读数与起点相同（类别仍为 safe-routed-raw-correct，融合决策仍为 `exact-views-and-independent-pixels`），丢失发生在候选档共用的原子归属物化：同一基线父框内有两个被接受的颜文字子编辑（dev-0011 父框 24 含 candidate-030 与 candidate-035；dev-0018 父框 15 含 candidate-016 与 candidate-017），`multiple-parent-face-edits` 规则让该父框的全部子编辑一起回退，父框按原字节还原，两条正确读数都被丢弃。起点使用的非原子物化允许同一父框多个子编辑，因此保留了这些结果。

## 起点自身的两处正文相交计数

新集上起点与所有候选档的 `new_body_intersection_errors` 都是 2，来自同样两个正文区域：dev-0008 的 region-14 与 dev-0055 的 region-12。两处都是正文以全角 `（` 结尾并紧贴右侧颜文字的行：候选的区域拼接保留了正文前缀的全部原字节（前缀、后缀和普通文字保护证明均通过），但替换区域的墨迹框向左延伸覆盖了正文尾部字形（分别含 1242 和 886 个正文像素），评测的拼接证明按设计拒绝任何覆盖正文像素的替换墨迹框，因此按新增正文相交错误计数；同一行的颜文字目标本身也未整串正确（尾缀 `✿` 与 `ノ` 未读出）。这两处不随候选档改变，所以候选档在该计数上没有新增，只是按绝对值计入而未通过门禁。

## 对下一步的事实约束

- 新集上 211/268 的目标在定位阶段丢失（部分覆盖 90、正文混入 116、无候选 5），而融合只丢失 7 个原始正确读数；改动融合规则的上界是 7，改动定位的上界是 211。
- 部分覆盖的主体是覆盖率 0.5–0.8 的候选（新集 55 个），对应手臂或尾缀被切。
- 正文混入全部来自正文像素，与正文行尾全角括号紧贴颜文字的版式直接相关；两处正文相交计数也来自同一版式。
- 候选档共用的原子归属物化规则在同一父框含两个颜文字时必然丢失两者；任何沿用该规则的候选档都会在这类行上落后于起点。
