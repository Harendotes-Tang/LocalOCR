## 为什么裁片 89.7% 不等于整图可用

历史裁片颜文字为 1076/1200（89.7%），历史卡片整图流程为 29/522（5.6%）；两者不是同一批目标。裁片已提供局部范围，整图流程还必须找到完整墨迹、安全分离正文、通过路由与多视图，再把结果正确融合。不能把两个比例相除解释为某个单环节的损耗。

此前在同一组 244 个开发目标上，用真值框和固定 4 像素边距取得原始 RGB 裁片，专项 raw 为 219/244，多视图规则为 192/244，自动最终为 20/244。这支持优先排查定位、归属和融合，而不能据此断言当前识别模型已足够或自动系统有 90% 上界。其中 61 个真值矩形仍混入正文；183 个无正文污染的矩形 raw 为 164、多视图为 147。真值框本身提供了自动系统尚未拥有的信息，这些均为开发诊断，不参与自动选框或独立验收。

## 改动与固定边界

- 新增可选 `fusion.pixel_ownership`：在原有融合保护全部通过后，用原始像素组件与括号归属抑制重复的无父框插入；完整墨迹和外侧手臂优先，歧义保留原结果。矩形相交或字符串相同不能单独确定归属。
- 新增可选 `candidate.local_windows`：围绕实际括号及邻近组件提出有界窗口，保留弱墨迹与完整核心笔画。候选和像素共享原上限，正文、邻居、独立像素、多视图保护保持启用。
- 评分前固定 `start`、`complete-exclusive`、`local-exclusive`、`joint` 四档。每档分别与同一组起点比较，前档失败不跳过联合档，不追加事后档位。
- 复用既有基线、专项和分类器，CPU 推理采用 2 个 intra-op / 1 个 inter-op 线程。本轮 GPU 预算为零，不训练，不新增 CTC 定位，不改变生产默认配置、API 或 APP。

`complete-exclusive` 为既有完整行范围加像素互斥；`local-exclusive` 为本轮局部窗口加互斥；`joint` 再加入既有局部归属证明。候选正确性必须经实际区域评分验证，机制测试本身不证明识别提升。

## 已核实的排重收益与缺口

上一轮已知的重复案例包含两条无基线归属的插入。本轮实际预测记录显示，短框被完整框抑制；记录了 416 个共享核心像素、相同括号锚点及保留完整外侧手臂的证据。原正确目标得以保留。这证明本轮声明的无归属插入间互斥确有作用。

新集的一处原正确丢失则属于另一种关系：原完整候选的对象、三张视图、融合决定和最终区域全部保持不变，新增短框也通过既有保护并进入最终区域。两者记录了同一原图中的相同括号笔画；完整候选带有基线归属，短框没有。当前互斥入口只接收无基线归属、无混合父框的已接受插入，无法比较这一对结果。

因此，新错误不是正确框被挤出预算、视图识别退化或父框恢复，而是基线替换与无归属插入同时贡献重复读数。这是本轮设计范围之外的已确认覆盖缺口，不能宣称“重复输出已全部解决”。本节依据绑定的原始开发预测、区域对齐和真值 JSON；未为该案例新增推理或重算共享掩码，记录的像素证据与新算像素数作了区分。私有逐目标证据仅存忽略目录。

## 下一轮建议与待确认边界

1. 先补跨归属互斥。把已接受的颜文字基线替换、区域拼接和无归属插入放入统一原始像素归属检查，比较实际颜文字墨迹范围，不能把整个正文父框都当作颜文字占用区。只抑制有充分共享证据的新重复读数；正文、相邻独立表达式、嵌套与外侧手臂仍须独立控制，歧义保留原结果。
2. 为定位引入可审计的位置提案。优先研究在基线已有行识别中保留 CTC 横向时间步，再由原始像素组件确定边界。固定比较组件提案、时间步提案和二者并集，候选/像素上限、识别器与融合保护保持一致。模型能提供时间步，只说明接口可复用，不证明其定位有效。
3. 若分层诊断显示大量目标彻底位于基线检测框外，再考虑单独训练定位/分割模型。训练需另外确认预算、数据与 CPU 约束；当前没有已训练定位器或此方向的效果证据。

位置映射必须绑定缩放、内容宽度、右侧 padding、批次宽度、逆透视与方向变换，区分符号重读前后的基线文字。安装库的词框接口会跳过空格、对非中文分组并估计平均列宽，不能直接当作精确颜文字字符框；横向时间轴也没有独立的纵向墨迹边界。同一模型的文本和位置是相关证据，不能替代独立像素或多视图保护。

专项识别发生在候选生成之后，不能把既有 ROI 时间步倒用为免费前置定位。如果新增专项父行识别，必须计入额外 CPU、内存及输入预算。旧预测没有保存时间步，无法从字符串重放恢复。本轮没有新增此类推理、定位或训练；上述内容须作为下一轮新决策与冻结后才能实施。

后续继续保留旧集 100/30、原正确零丢失、正文/负样本零新增和全部三轮合并 p95 的门槛；另建排除本轮已见核心/文本的新数据。所有未用保留集保持封存，不因开发失败改作调参材料。六类归因支持优先补完整边界与正文归属；跨归属重复和父框物化则作为必须零退化的独立控制。
