# 2026-10-15 真实渲染下的括号证据：核心墨迹阈值与外括号宽度裁决

[返回 README 评测结果](../../../README.md#评测结果) · [历次版本对比](../../../README.md#历次版本对比)

本轮不训练、不改专项模型与分类器，GPU 账本上限为 0 秒，只给研究链路增加两个可选配置键；冻结配置缺省这两个键时，新代码在上轮 100 张开发场景与 14 张已知输入截图上逐项复现上轮记录的候选、区域与决策（等价性探针 0 不一致）。起点是对[候选定位轮](../region-candidates-20261013/README.md)已知输入首测 4/50 的按卡片位置逐面归因：46 处失误中 20 处只差最外层括号的宽度（专项在真实界面字体上把半角 `(` 读成全角 `（`，加边距视图又让右括号在 `)`/`）` 间翻转），另有相当部分因抗锯齿晕边把括号与相邻字形粘成一个连通域而检不出括号对（基础掩码上独立面只检出 26/50 对，同一掩码把对比度阈值提到 80 或 120 时为 34 或 42 对）。该集合因此被逐面查看，在本轮降级为开发探针，其后的真实计数均标注为非独立。

- `shape_contrast_threshold`：括号形状检测与括号对内部计数改用核心墨迹掩码，候选包络、覆盖率、字形单元与像素计数仍用阈值 8。开发集与探针上比较 8/48/80/120：阈值 80 与 120 首次出现各 1 处“正文新增错误”，逐例核查为正确的整读替换（如 `(∀T)`→`(◎∀T)` 即真值），但去晕边同时把致密 CJK 字形拆成细笔画，形似括号的笔画与真括号构成最宽的伪括号对，使区域墨迹框覆盖正文而通不过正文保持校验。新增规则：核心掩码笔画若落在基础掩码的致密整字形连通域内不作括号证据（按连通域而非 2 px 字形单元判定，第一版按单元判定剔除了与致密眼部字形相邻的真括号）。修正后 48 与 80 在三套开发集上整串相同且门禁全过，探针 15/50 对 16/50、内嵌 10/35 对 12/35、核心括号对 54 对 70，冻结 80。
- `outer_bracket_width`：视图对最外层括号对（原子表 NFKC 宽度家族）先按去宽度键投票，其余字节仍逐字节一致且原始视图必须持有；一致后宽度取首遍基线对同一括号的读数（拼接进宽正文框的候选取父框文本），基线无同族括号时取原始视图；决策记录 `bracket_width_source`。阈值 48 下三种模式对比：探针整串 `exact` 5/50、`baseline-else-raw` 15/50（13 错转对、0 对转错、正文零丢失）、`raw` 5/50；合成开发集上 `baseline-else-raw` 整串下降（cards-v4 10→6、atoms-mixed-v3 30→20），因为合成真值按原子表均匀采样半角与全角括号而基线多读半角，差额全部记为“仅宽度不符”的诊断计数；门禁全部通过。冻结 `baseline-else-raw`，评测口径不做宽度归一化。
- 桥接比例 0.6 对 0.45（阈值 80）：cards-v4 安全完整覆盖 27→32、atoms-mixed-v3 113→116，整串与探针逐项相同、卡片 CER 略差，保持默认 0.45。
- 新数据 cards-v4（卡片生成器 v3）与 atoms-mixed-v3（混合生成器 v2）在一半文本段上施加 −1/−2 px 紧排模拟真实字体的粘连（渲染器 `tracking` 为布局参数，字形栅格与掩码不变）；cards-v3 与 atoms-mixed-v2 的保留集降级为开发回归。
